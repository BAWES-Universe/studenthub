## Breaking Changes

### Local Development
- **Before:** Access via ports (e.g., `localhost:21080`), required `-f docker-compose-dev.yml`
- **After:** Access via domains (e.g., `admin.studenthub.local`), just use `docker-compose up`
- **Note:** Port access still works for backward compatibility
- **Simplified:** Default `docker-compose.yaml` means no `-f` flag needed for dev

### Environment Initialization
- **Before:** Hardcoded cookie validation keys
- **After:** Auto-generated keys (must run `./init`)

2. **Pull latest changes:**
   ```bash

   ```

3. **Restart services:**
   ```bash
   docker-compose down
   docker-compose up -d
   ```

4. **Access via new domains:**
   - Use `admin.studenthub.local` instead of `localhost:21080`

### For DevOps

1. **Review GitHub Actions workflow:**
   - Check `.github/workflows/docker-build.yml`
   - Verify image tags match deployment needs

2. **Configure Railway (if using GHCR images):**
   - Switch to Docker image deployment
   - Set image: `ghcr.io/owner/repo/backend-railway-prod:latest`
   - Add `GITHUB_TOKEN` secret

3. **Update deployment scripts:**
   - Replace ECR references with GHCR (if migrating)
   - Update authentication methods

## Known Issues / Limitations

### Traefik
- Dashboard is HTTP only (local dev only)
- Requires /etc/hosts modification
- Not used in production (Railway uses nginx)

### GitHub Actions
- First build may be slow (no cache)
- Private repos require authentication
- Build time depends on Dockerfile complexity

## Rollback Plan

If issues arise:

1. **Traefik Issues:**
   - Use port-based access (still works)
   - Remove Traefik service from docker-compose.yaml
   - Revert to previous version from git history

2. **GitHub Actions Issues:**
   - Build manually: `docker build -f Dockerfile-nginx-prod .`
   - Push to ECR if needed
   - Disable workflow in GitHub

3. **Environment Issues:**
   - Restore old `environments/index.php` from git history
   - Re-add hardcoded keys if needed (not recommended)
